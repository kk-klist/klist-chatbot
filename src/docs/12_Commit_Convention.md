# 커밋 메시지 컨벤션

## 기본 형식

커밋 메시지는 Conventional Commits 형식을 따르고 제목은 한글로 작성한다.

```text
type(scope): 한글 요약
```

`scope`는 변경 범위를 명확하게 표현할 때만 사용하며 생략할 수 있다.

```text
type: 한글 요약
```

## Type

| Type | 용도 |
| --- | --- |
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 기능 변경 없는 코드 구조 개선 |
| `test` | 테스트 추가 또는 수정 |
| `docs` | 문서 변경 |
| `chore` | 개발 환경이나 기타 유지보수 작업 |
| `build` | 빌드 설정과 의존성 변경 |
| `ci` | CI/CD 설정 변경 |
| `perf` | 성능 개선 |
| `style` | 동작에 영향 없는 코드 형식 변경 |
| `revert` | 이전 커밋 되돌리기 |

## 작성 규칙

- Type은 영문 소문자로 작성한다.
- 제목은 한글로 작성한다.
- 제목 끝에 마침표를 붙이지 않는다.
- 제목은 변경 결과를 간결하게 설명한다.
- 서로 독립적인 작업은 작업 단위별 커밋으로 분리한다.
- 기능과 테스트가 하나의 완료 조건이면 같은 커밋에 포함할 수 있다.
- 관련 없는 리팩터링이나 문서 변경은 별도 커밋으로 분리한다.
- API 또는 설정처럼 범위가 유용할 때만 소문자 scope를 사용한다.

## 예시

```text
feat: TourAPI 호출 간격과 재시도 정책 적용
fix(chat): LLM 타임아웃 오류 분류 수정
refactor: 챗봇 공통 오류 타입 통합
test(search): 관광지 색인 일관성 테스트 추가
docs: 서킷 브레이커 도입 기준 정리
build: Elasticsearch 테스트 의존성 추가
```

## Breaking Change

호환되지 않는 변경은 Type 또는 scope 뒤에 `!`를 붙이고 본문에 영향을 기록한다.

```text
feat(api)!: 내부 채팅 요청 계약 변경
```

단, API 계약 변경은 `99_Autonomous_Development_Policy.md`에 따라 사용자 확인 후 진행한다.
